# GroovePH landing page — Performers/Coaches sections and Filipino CTA motif

Two new feature-showcase sections ("For Performers" and "For Coaches") were inserted between the existing Features section and the CTA, and the CTA card received a Filipino-inspired decorative SVG overlay. The navbar gained `Performers` and `Coaches` entries with intersection-observer active-link tracking. A prior reviewer cycle already caught two gaps — un-linked cards and hardcoded PH hex in eyebrow styles — both were fixed in a follow-up commit. Watch for: the `wm-*` keyframes added to `globals.css` were missing before this diff while `WelcomeModal.tsx` already referenced them by name; the diff resolves a latent bug but the reduced-motion guard it introduces is not yet wired to the modal DOM node.

**Verdict**: APPROVED

## High-level view

Both new sections use the established section-component pattern: `g-section` / `g-section-alt`, `g-container`, `<SectionHeader>`, `<Reveal className="g-reveal-stagger">`, and `g-card g-card-hover` cards wrapped in `<Link>` for full keyboard navigability.

Philippine flag palette appears in two forms: literal hex values (`#FCD116`, `#0038A8`) inside SVG fill/stroke attributes in the CTA background — correct, since SVG presentation attributes cannot consume CSS custom properties — and CSS `var(--ph-blue)` / `var(--ph-red)` references for the eyebrow left-border accents, backed by `--ph-*` tokens declared in the `@theme` block.

The `wm-*` keyframe block added to `globals.css` resolves a pre-existing silent failure: `WelcomeModal.tsx` had been referencing `wm-spotlight-pulse`, `wm-logo-pop`, `wm-text-up`, and `wm-eq-rise` without those keyframes being defined anywhere. The reduced-motion guard introduced alongside them (`.wm-reduced *`) is not yet applied to the WelcomeModal root, so users who prefer reduced motion will still see the animations play.

Section order is Hero → Disciplines → Stats/Mission → Studios → How It Works → Features → **Performers → Coaches →** CTA, matching the spec exactly.

### Filipino palette — SVG vs CSS boundary

The CTA background SVG hard-codes `#FCD116` and `#0038A8` as presentation attributes on `<g fill>`, `<line stroke>`, `<polygon fill>`, and `<path fill>`. SVG presentation attributes don't inherit CSS custom properties, so using `var(--ph-yellow)` there would silently produce `transparent`. The literal hex is the only correct choice here. The eyebrow border accents in HTML correctly reference `var(--ph-blue)` and `var(--ph-red)`.

### WelcomeModal reduced-motion guard incomplete (possible)

`WelcomeModal.tsx` now has keyframes defined, closing the silent-no-op bug. The diff also adds a `.wm-reduced *` selector that sets `animation: none !important` and `transition: none !important`. However, the selector is only effective when `.wm-reduced` is present on an ancestor DOM node — and no code in `WelcomeModal.tsx` adds this class. Without that, the guard is dead CSS. The fix is to read `prefers-reduced-motion` in the component (or use a media query in the keyframe itself with a `from/to` that produces no change) and conditionally apply the class to the modal wrapper. Confidence: confirmed — the class is defined but never applied.

### Support Tickets href indirection

The Coach section's "Support Tickets" card links to `/coach/home` — the authenticated coach dashboard where the ticket modal lives — rather than a direct deep-link to the modal. The card description says "Submit issues to the admin team," which accurately represents the destination. A public landing page cannot link directly to a modal trigger behind authentication, so the redirect-to-dashboard pattern is the practical ceiling here.
