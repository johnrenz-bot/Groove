# GroovePH landing page — performers/coaches sections and Filipino CTA decoration

Two new landing sections ("For Performers" and "For Coaches") are inserted between the existing Features section and the CTA. The CTA receives an inline decorative SVG with a Philippine sun-ray burst, three five-pointed stars, and a wave band. Navigation links and intersection-observer section IDs are updated to include the new sections. All changes are purely additive — zero existing content removed. Watch for: feature card `href` values are defined but never wired to any `<Link>`, making every card a non-navigable static element despite the per-feature route data sitting unused in the constant arrays.

**Verdict**: CHANGES_REQUESTED

### Feature cards are informational, not navigable

Every card in both sections stores a destination route — `/client/talent`, `/client/appointments`, `/coach/talents`, etc. — but the JSX map renders a bare `<div key={feature.title} className="g-card g-card-hover ...">` with no `<Link>` wrapper. The `href` field is consumed nowhere. A user hovering a card gets the `g-card-hover` visual treatment but clicking does nothing.

The FEAT-001 step 2 spec says "CTA button: 'Join as Performer' → links to /register/client" (which is correctly wired), but it also says "6 feature cards linking to real routes" — implying the cards themselves should navigate. The fix is to wrap each card in `<Link href={feature.href}>` or at minimum add a "Learn more →" anchor inside the card body. The Support Tickets `href: '#'` would then become a visible broken link and needs a real destination (e.g., a `mailto:` or an in-app support route).

### Philippine hex in inline border styles

The two eyebrow `<span>` elements use `style={{ borderLeftColor: '#0038A8' }}` and `style={{ borderLeftColor: '#CE1126' }}` inline. These are borders on text-adjacent decorative elements, which is debatable as "SVG/border elements." The project constraint says SVG decorative elements are the sanctioned location for flag hex. If this passes review, the inconsistency is minor — the values are clearly decorative and don't affect token-driven text or background colors. If strict enforcement is desired, the values belong in a CSS custom property (e.g., `--ph-blue: #0038A8`) defined in `globals.css` and referenced via `var(--ph-blue)`.
